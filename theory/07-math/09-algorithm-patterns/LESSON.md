# Algorithm Patterns and Hard Coding

This topic explains algorithm patterns used in hard problems and puzzles. These patterns are the building blocks for low-level problem solving.

## Common patterns

- **Iteration**: loop over data with `for`, `while`, or `do while`.
- **Recursion**: call a function from itself to explore many possibilities.
- **Backtracking**: try a choice, then undo it if it fails.
- **Divide and conquer**: split a problem into smaller subproblems.
- **Greedy**: take the best immediate choice and move forward.

## How to approach hard code problems

1. read the problem carefully.
2. identify the data structure: array, matrix, stack, or tree.
3. write a simple version first.
4. add checks for invalid cases.
5. use recursion or loops to explore possibilities.
6. test with small examples before scaling.

## Puzzles that use these patterns

- N-Queens uses backtracking and board state tracking.
- Fibonacci uses iteration or recursion.
- Prime checking uses loops and division.
- Square root approximation uses binary search or iterative refinement.
- Search problems use loops and conditional logic.

## Low-level notes

- A low-level solution often uses arrays and integer math, not high-level data structures.
- Keeping state compact helps reduce memory usage.
- Hard problems are good practice for writing clear, step-by-step code.
